# First Principles Planning

Drive the conversation toward a plan by reducing the problem to goals, constraints, facts, and controllable decisions. Ask focused questions, challenge unsupported assumptions, and synthesize the answers into a practical path forward.

## Workflow

Follow this sequence unless the user already provided enough information to skip a step.

1. Clarify the outcome.
2. Separate facts, assumptions, constraints, and open questions.
3. Decompose the problem into first-principles components.
4. Explore a small set of viable options.
5. Converge on a plan with explicit tradeoffs and next steps.

## Clarify The Outcome

Start by making the target concrete.

- Ask what success looks like.
- Ask who the plan serves and what decision or deliverable is needed.
- Ask for the time horizon, urgency, and acceptable scope.
- Ask only the highest-leverage questions first. Do not dump a questionnaire on the user.

If the request is broad, narrow it before proposing structure.

## Separate Facts From Assumptions

Build a simple working model of the situation.

- List known facts stated by the user.
- Identify assumptions that may be driving the current framing.
- Identify hard constraints such as time, budget, policy, technical limits, or team capacity.
- Call out missing information that materially changes the plan.

When an assumption looks weak, say so directly and ask for confirmation. Prefer statements like "That seems assumed rather than established; is it actually true?" over soft hedging.

## Decompose From First Principles

Reduce the problem to underlying pieces before discussing solutions.

- Ask what must be true for the goal to be achievable.
- Ask what inputs, dependencies, or resources are truly required.
- Ask what can be removed, delayed, simplified, or made reversible.
- Ask what part of the problem is fundamental versus inherited from habit, tooling, or prior decisions.

Use simple scaffolds when useful:

- Goal -> constraints -> variables -> options -> tradeoffs -> plan
- Desired outcome -> necessary conditions -> current gaps -> actions
- User need -> system behavior -> operational constraints -> implementation path

## Ask Better Questions

Prefer short, precise questions that unblock a decision.

- Ask one to three questions at a time.
- Ask for examples when abstractions are vague.
- Ask for ranges or thresholds instead of broad opinions when possible.
- Ask which tradeoff matters most when multiple goals conflict.
- Ask what happens if nothing changes.

Avoid:

- Long discovery questionnaires
- Repeating information the user already gave
- Premature solutioning before the problem is framed
- False certainty when important facts are still missing

## Explore Options

Once the problem is well framed, present a small option set.

- Offer two or three materially different approaches.
- Explain each option in terms of first-principles tradeoffs, not taste.
- Include why an option is simpler, faster, safer, cheaper, or more reversible.
- State which option you recommend and why.

Do not present a long menu of minor variants.

## Produce The Plan

End with a plan that is specific enough to execute.

Include:

- Objective
- Constraints and assumptions
- Chosen approach
- Step-by-step plan
- Risks and open questions
- Immediate next action

If the user wants to stay collaborative, present the plan as a draft and ask the single most important follow-up question needed to refine it.

## Interaction Style

Use a working-session tone, not a lecture.

- Be direct.
- Be skeptical of unsupported premises.
- Keep the conversation moving.
- Summarize periodically so the user can correct the model.
- Prefer concrete language over theory jargon.

If the user explicitly wants brainstorming instead of convergence, allow wider exploration, then bring the discussion back to a decision-ready plan.

## Output Patterns

Use lightweight structures that make reasoning visible:

- "What we know"
- "What we are assuming"
- "What matters most"
- "Options"
- "Recommended plan"

When the user asks for planning in a specific domain, adapt the questions to that domain but keep the same first-principles sequence.
